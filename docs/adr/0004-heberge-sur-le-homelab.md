# Hébergé sur le homelab, pas dans le cloud

Le pont Bluetooth doit tourner à côté du téléphone passerelle, donc sur le serveur du homelab (UM880). Tout le produit (interface, API, base, pont) y tourne, en Docker sauf le pont qui a besoin du Bluetooth et de l'audio de l'hôte, plutôt que de séparer une interface cloud d'un pont local : lancer un appel reste un appel local et il n'y a qu'un déploiement. L'interface de l'opérateur n'est joignable que par le tailnet, et rien n'est exposé sur Internet : la fin d'appel est relevée par interrogation de l'API ElevenLabs, et les outils d'agenda sont exécutés par la ligne elle-même (ADR 0002). Le produit s'arrête quand le serveur s'arrête, ce qui est acceptable pour une démo lancée par l'opérateur. Un éventuel mode vitrine serait exporté et hébergé ailleurs, jamais servi par le homelab.

La fin d'un appel est détectée par la ligne elle-même (fin de session), puis le serveur interroge l'API ElevenLabs jusqu'à ce que la conversation soit traitée. Le webhook de fin d'appel n'est donc pas nécessaire.
