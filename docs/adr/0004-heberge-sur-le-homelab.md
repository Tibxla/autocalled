# Hébergé sur le homelab, pas dans le cloud

Le pont Bluetooth doit tourner à côté du téléphone passerelle, donc sur le serveur du homelab (UM880). Tout le produit (interface, API, base, pont) y tourne, en Docker sauf le pont qui a besoin du Bluetooth et de l'audio de l'hôte, plutôt que de séparer une interface cloud d'un pont local : lancer un appel reste un appel local et il n'y a qu'un déploiement. L'interface de l'opérateur n'est joignable que par le tailnet ; seuls les points d'entrée appelés par ElevenLabs (outils d'agenda, webhook de fin d'appel) sont publics via Tailscale Funnel, chacun authentifié. Le produit s'arrête quand le serveur s'arrête, ce qui est acceptable pour une démo lancée par l'opérateur. Un éventuel mode vitrine serait exporté et hébergé ailleurs, jamais servi par le homelab.
